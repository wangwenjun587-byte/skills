# douyin-web-user-csv

## Overview

将“关键词搜索抖音 Web 用户 -> 进入用户列表 -> 按条件筛选 -> 生成用户概要 -> 写入 CSV”的流程做成稳定工作流。

默认参数：
- `关键词`：必填
- `粉丝数要求`：可选，默认 `100000`
- `是否蓝v`：可选，默认 `false`
- `获取用户数量`：可选，默认 `10`

输出字段：
- 抖音名称
- 抖音号
- 粉丝数
- 蓝V认证名称
- 用户概要

## Direct Invocation

当用户要“直接跑”这个技能时，按下面执行：

1. 检查并编辑 `config.json`
2. 首次运行时允许浏览器弹出，并在需要时人工登录抖音
3. 执行导出脚本：

> ⚠️ **执行方式说明：**
> 脚本运行时间约 1~3 分钟（含浏览器导航、滚动、解析），**必须使用同步方式执行**（即 `execute_shell_command` 直接调用，不要用 `nohup ... &` 后台运行）。
> 后台运行会导致 agent 无法感知完成时机，只能靠轮询日志，用户体验会很差。
> 直接同步调用，脚本退出时结果立刻返回，无需额外等待。

```bash
python3 active_skills/douyin-web-user-csv/scripts/run_export.py \
  --keyword <关键词> \
  --min-fans <粉丝数要求> \
  [--bluev-only] \
  --limit <获取用户数量>
```

参数映射：
- `关键词` → `--keyword`
- `粉丝数要求` → `--min-fans`
- `是否蓝v=true` → 加 `--bluev-only`
- `获取用户数量` → `--limit`

脚本职责：
- 拉起或复用本地浏览器
- 自动打开抖音搜索结果页
- 通过 CDP 读取 `document.body.innerText`
- 解析用户卡片
- 换算粉丝数并筛选
- 按蓝V条件过滤
- 生成 20 字内用户概要
- 写 CSV / JSON

## Workflow

### 1. 明确参数

缺少参数时，按下面规则处理：
- 没给 `关键词`：必须先问
- 没给 `粉丝数要求`：使用 `100000`
- 没给 `是否蓝v`：使用 `false`
- 没给 `获取用户数量`：使用 `10`

建议先把本次参数整理成：

```text
关键词: 设计师
粉丝数要求: 100000
是否蓝v: false
获取用户数量: 10
```

### 2. 打开抖音 Web 搜索页

技能会自己启动或复用本机 Chrome / Edge，并使用独立 profile 保存登录态。

实际流程：
1. 打开 `https://www.douyin.com/`
2. 如未登录，等待人工登录
3. 自动导航到：

```text
https://www.douyin.com/search/<关键词URL编码>?type=user
```

例如：

```text
https://www.douyin.com/search/%E8%AE%BE%E8%AE%A1%E5%B8%88?type=user
```

### 3. 进入“用户”结果并读取页面文本

当前实现直接通过 CDP 执行 `document.body.innerText`。

经验规则：
- 抖音 Web 结果页常有文本粘连，尤其是“抖音号 / 获赞 / 粉丝数”之间
- 不要过度依赖 aria 节点名称的完整结构
- 优先从用户卡片文本块整体提取，再做解析

### 4. 解析用户卡片

目标是拿到每个候选用户：
- 抖音名称
- 抖音号
- 粉丝数
- 蓝V认证名称
- 用户简介

推荐做法：
1. 找出包含 `抖音号:` 且包含 `粉丝` 的文本块，作为候选卡片
2. 对每个卡片按换行切分
3. 第一行通常是抖音名称
4. 若出现 `认证徽章`，其后紧邻的一行通常可视为蓝V认证名称
5. `抖音号:` 所在行中继续解析抖音号、获赞数、粉丝数
6. 卡片后续文本拼成用户简介

### 5. 处理抖音 Web 文本粘连

这是本技能最关键的容错点。

页面经常出现类似：

```text
抖音号: zll12051026574.2万获赞141.3万粉丝
```

这里 `抖音号` 和 `获赞数` 粘连，不能简单按空格切。

处理原则：
- 以 `获赞` 和 `粉丝` 作为锚点切分
- 抖音号取 `抖音号:` 与 `获赞` 之间的前半段，但要警惕末尾数字可能属于获赞数
- 如果解析置信度低：
  - 保留当前值，但在回复中说明“字段可能存在网页文本粘连”
  - 若用户要求高准确度，再逐个点进主页复核

### 6. 粉丝数筛选

将中文粉丝数转换为可比较数字后筛选。

换算规则：
- `x万` → `x * 10000`
- `x亿` → `x * 100000000`
- 纯数字 → 直接转数值

只保留 `粉丝数 >= 粉丝数要求` 的用户。

### 7. 蓝V筛选

若 `是否蓝v=true`：
- 仅保留有 `蓝V认证名称` 的用户
- 没有认证名的记录直接过滤

若 `是否蓝v=false`：
- 保留全部符合粉丝要求的用户

### 8. 生成用户概要

根据用户简介生成一个不超过 20 字的 `用户概要`。

要求：
- 20 字以内
- 直白、便于后续筛选或私信
- 不要复述完整简介
- 尽量提炼为“定位 + 内容风格”

好例子：
- 装修避坑好家设计
- 法式奶油风设计
- 现代极简智能家居
- 北京设计交流向
- 奶油风家居美学

避免：
- 太空泛：`设计师博主`
- 太长：`一个分享现代极简风和装修避坑经验的设计账号`
- 带主观判断：`看起来挺专业的设计师`

### 9. 截取数量并写 CSV

按结果出现顺序保留前 N 条，N = `获取用户数量`。

默认输出目录：

```text
~/3chatclaw-data/douyin-web-user-csv-output/
```

文件名建议：

```text
douyin_<关键词>_用户列表.csv
```

JSON 文件名：

```text
douyin_<关键词>_用户列表.json
```

CSV 表头固定为：

```text
抖音名称,抖音号,粉丝数,蓝V认证名称,用户概要
```

使用 UTF-8 with BOM 写入，避免中文在表格软件里乱码。

### 10. 回复用户

完成后简要汇报：
- 关键词
- 粉丝数要求
- 是否蓝V
- 实际写入条数
- CSV 文件路径
- 如果有字段粘连风险，要明确说明

示例：

```text
已完成抓取并写入 CSV。
关键词：设计师
粉丝数要求：100000
是否蓝V：否
写入条数：10
文件路径：~/3chatclaw-data/douyin-web-user-csv-output/douyin_设计师_用户列表.csv
说明：抖音 Web 个别账号字段可能因页面文本粘连存在轻微误差；如需更高准确度，可继续逐个主页复核。
```

## Accuracy Escalation

当用户说这些话时，进入高精度模式：
- 校正字段
- 逐个核验
- 确认抖音号
- 确认蓝V
- 提高准确率

高精度模式做法：
1. 从结果列表中逐个打开候选用户主页
2. 主页复核抖音号、粉丝数、认证信息
3. 再回写 CSV

这一步更慢，但比直接解析列表文本更准。

## Failure Handling

遇到这些情况时按以下方式处理：

### 搜索页打不开 / 未登录限制
- 先确认 `config.json` 中浏览器路径可用
- 若未登录，按提示在浏览器中完成人工登录
- 再次自动导航到 `search/<关键词>?type=user`
- 若仍失败，向用户说明当前 Web 端受限

### 结果不足
- 如符合条件的用户少于目标数量，写入实际数量即可
- 回复里明确写“仅找到 X 条符合条件的结果”

### 文本结构异常
- 优先保住 CSV 输出，不要卡死
- 允许先生成“可用版 CSV”
- 再告诉用户可继续做字段校正

## Output Quality Rules

- 不编造不存在的蓝V认证名称
- 不把简介误写到抖音名称字段
- 用户概要必须 ≤20 字
- 输出前检查 CSV 列顺序是否固定
- 文件名中保留关键词，便于后续批次管理

## Config

首次使用前：

```bash
cp active_skills/douyin-web-user-csv/assets/config.example.json \
  active_skills/douyin-web-user-csv/config.json
```

重点字段：
- `browser.type`
- `browser.exe_path`：留空时自动探测，探测失败再手填
- `browser.user_data_dir`：留空时按系统使用默认 profile 目录
- `cdp_port`
- `page_wait_timeout_sec`（基础稳定等待；当前实现另外强制等待用户卡片特征词，最长至少 180 秒）

浏览器启动说明：
- Windows 会优先探测 `Program Files`、`Program Files (x86)`、`LOCALAPPDATA` 下的 Chrome / Edge
- macOS 会优先探测 `/Applications` 和 `~/Applications`
- macOS 在 Apple Silicon 机器上，会先用 `sysctl` 判断真实硬件，再用 `lipo -archs` 判断浏览器是否包含 `arm64` slice；只有两者都满足时，才会通过 `arch -arm64` 启动浏览器
- Linux 继续保留 `/usr/bin/...` 和 `~/.copaw/browser-bin` 的 fallback 逻辑

依赖：

```bash
uv pip install -r active_skills/douyin-web-user-csv/scripts/requirements.txt
```

如果已经手头有历史 raw 文本文件，仍可继续直接调用：

```bash
  --json-output ~/3chatclaw-data/douyin-web-user-csv-output/douyin_<关键词>_用户列表.json
```
