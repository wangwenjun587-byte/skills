# 抖音-超级前台

## Skill Text Header
- Skill: `抖音-超级前台`
- Skill ID: `douyin-web-comment-notify-reply-dm`
- Entry: `scripts/task_entry.py`
- Execution: 本地 Chrome + CDP
- Platform: macOS / 本地可见 Chrome / 抖音 Web
- Scope: 评论通知读取、按通知打开、评论区公开回复

## Overview

这个 skill 已固化为一条稳定主链路，并默认采用模式 A（运行时提取评论通知、自动选择 1 条目标通知执行）：

1. 登录检查
2. 打开右上角通知面板
3. 提取评论通知
4. 自动选择 1 条待处理通知并按 `notification_key` 打开目标通知
5. 进入对应视频评论区
6. 基于通知内容定位目标评论并进入真实回复态
7. 真实输入回复文本
8. 真实发送一次公开回复

当前 skill **不负责私信**。如需私信，交给现有 skill `douyin-web-send-dm`。

## Runtime & Implementation Conventions

- 默认入口：`scripts/task_entry.py`
- 默认执行模型：**本地 Chrome + CDP**
- 外层允许由当前宿主环境进入；若宿主通过 `uv` 调起，只作为入口层使用
- skill 内部脚本之间统一使用宿主 Python（`sys.executable` / `python3`），不做 `uv run` 套娃
- CDP 仅连接本地 `127.0.0.1` / `localhost`
- 在 macOS Apple Silicon 上，Chrome 启动必须强制使用 `arch -arm64`
- 调试与验证默认使用**非 headless、可见 Chrome**
- 以**真实页面结果**优先于脚本 `ok=true`

## Stable Workflow

### Step 1. Login Check

脚本：`scripts/douyin_login_check.py`

职责：
- 确认 Chrome / CDP 可用
- 导航到抖音主页
- 判断是否已登录
- 识别右上角通知入口是否可用

说明：
- 已增加页面 ready 后的额外 settle 延迟，避免首页刚加载完成时过早误判

### Step 2. Open Notifications

脚本：`scripts/douyin_open_notifications.py`

职责：
- 定位右上角“通知”入口
- 展开通知面板
- 确认右侧通知区域已打开

### Step 3. Extract Comment Notifications

脚本：`scripts/douyin_extract_comment_notifications.py`

职责：
- 只提取**完整评论通知卡**
- 为每张真实通知卡生成一个 `notification_key`

当前固化后的通知卡筛选口径：
- 位于右侧通知区域
- 尺寸接近完整卡，当前实测约 `310x78`
- 卡内存在右侧 `48x48` 视频缩略图
- 文本满足评论通知语义（如“评论了你的作品”）

当前结果已从旧版的“同一张卡被拆成 3 个 key”收敛为：
- **一张真实通知卡 = 一个 key**

### Step 4. Open Comment Notification

脚本：`scripts/douyin_open_comment_notification.py`

职责：
- 优先按 `--notification-key` 选中目标通知卡
- 点击该卡右侧 `48x48` 视频缩略图
- 打开视频详情 modal，并进入评论区上下文

成功标准：
- URL 含 `modal_id=`
- 页面可见 `全部评论`

### Step 5. Activate Target Comment Reply State

脚本：`scripts/douyin_activate_comment_reply_input.py`

职责：
- 在评论区按 `--target-comment-snippet` 定位目标评论
- 优先采用 `direct-target-container` 主路径
- 只点击目标评论容器内的“回复”入口
- 让底部公共输入栏进入真实回复态

真实成功信号：
1. 回复按钮切换为 `回复中`
2. 输入栏出现 `回复@...: ...`
3. 输入区获得焦点，可直接录入

### Step 6. Type Reply Text

脚本：`scripts/douyin_type_comment_reply_text.py`

职责：
- 在真实回复态下，用接近真实人工输入的方式录入文本
- 不使用 `textContent` / `innerHTML` / `execCommand` 伪输入
- 通过 CDP 键盘事件完成真实录入

成功标准：
- 输入框当前值包含目标文本
- placeholder 消失
- 发送按钮出现

### Step 7. Send Comment Reply

脚本：`scripts/douyin_send_comment_reply.py`

职责：
- 只发送当前输入框中已真实录入的文本
- 不覆盖 Step 6 已输入内容

成功标准：
- 评论区出现新回显，或
- 回复态清除并出现等价强成功信号
- 以真实页面观察为准，且只算发送一次

## Current Stable Keys Model

当前通知层已固化为：
- 只对完整通知卡生成 key
- `notification_key` 不再依赖 `panel_index`
- 主要基于以下字段组合生成：
  - `text`
  - `thumb_src`
  - `date_fragment`
  - `author_hint`
  - `comment_hint`
  - `self_attrs`
  - `parent_attrs`

这一步用于避免：
- 同文案通知被纯文本去重吞掉
- 同一张通知卡因 DOM 子节点被拆成多个 key

## Safety Rules

- 未登录时立即停止
- 无法确认目标评论时不要发送
- 页面进入坏态时不要续跑，应从头重开
- 回复成功判断必须以真实 UI 强信号为准
- 不依赖随机 class 名做长期定位
- 不重复发送，不覆盖已输入文本
